# Threadbook.Storage

Package reference example: `<PackageReference Include="Threadbook.Storage" Version="0.4.0-beta.1" />`.

Original MIT .NET 10 implementation. Dependency graph: desktop -> Storage -> Core; Storage uses only Core and BCL. No networking, telemetry, third-party packages or assembly-import background work. Caller serializes operations and disposes the owning JsonStore and returned streams. Independent directories support independent owners; one exclusive owner per directory.

```csharp
using var owner = new JsonStore(explicitNewDirectory);
var notes = new NotebookService(owner);
var metadata = new LibraryStore(owner);
var library = new LibraryService(metadata, () => notes.State);
var attachments = new AttachmentStore(owner, library);
using var bytes = new MemoryStream(new byte[] { 1, 2, 3 });
var stage = attachments.Stage(notes.State.Notes.First().Id, bytes,
    "sample.bin", "application/octet-stream");
var outcome = attachments.AddToNote(stage);
if (!outcome.Success) attachments.Discard(stage);
```

JsonStore.Load/Commit implement ISnapshotStore with expected-revision checking, bounded strict Snapshot schema-1 JSON and atomic single-file replacement; 25 MiB payload limit. RecoveryStore(owner) retains drafts/sessions through the same provider. Ordinary rotating backups retain five prior versions; preserved damaged files are separate. Recovery validates a backup and preserves damaged primary bytes. This does not guarantee survival of hardware failure or provide a multi-file crash transaction.

LibraryStore(owner) implements ILibraryStore over library.json schema 1 (8 MiB/depth 32). Load normalizes stale canonical references; corrupt/future bytes remain untouched and block writes. Reset(canonical) explicitly preserves originals first. AttachmentStore.Stage writes a managed GUID blob before AddToNote commits metadata; discard abandoned stages and dispose OpenRead streams. Remove unlinks metadata and cleans the blob. SHA256 verifies bytes, not trust. Limits: 25 MiB each, 512 MiB/10,000 attachment records. Desktop performs bounded PNG/JPEG decoding; other files remain opaque.

JsonStore.CreateEncrypted(newDirectory,password) and OpenEncrypted(directory,password) return disposable owners; IsEncryptedDirectory detects the public header. Lock wipes the owned key; Unlock rederives/authenticates it. Files (IVaultFiles) supplies bounded logical-key Read, WriteAtomic, List, Delete, Exists, raw ReadStored, PreserveStored and ReadCryptoHeader; AssertLiveOwner rejects locked/disposed use. Paths are restricted to managed classes. AES-256-GCM per payload uses 12-byte nonce/16-byte tag and authenticated vault/key/header context; PBKDF2-SHA256 uses salt32 and exactly 600,000 iterations. Physical names remain visible. Complete managed-memory erasure cannot be guaranteed. No password recovery.

VaultCopies.CreateEncryptedCopy(owner,newDirectory,password) returns a verified disposable encrypted owner. Destination must be absent; unknown/reparse files reject. Original plaintext files/backups remain unchanged. Copy budgets: 20,000 entries, 25 MiB/payload, 1 GiB aggregate. No implicit conversion or plaintext fallback.

PortableLibrary.CreateBackup(owner,stream,cancellation) captures managed files/hashes and ciphertext/public header for encrypted vaults. Restore(stream,newDirectory,password,cancellation) validates into a NEW directory only (no current-vault merge/overwrite). Caller owns archive streams. Restore checks paths, duplicates, hashes and expanded budgets (20,000 entries/1 GiB; 4 MiB manifest). Encrypted restores authenticate payloads with password. Reads/imports throw DataException on invalid input; mutations return Outcome.

NoteImports.PrepareMarkdownImport(current,paths,targetNotebook,cancellation) and PrepareJsonAppend(incoming,current) return an append/remapped Snapshot, with no store mutation; host confirms then commits once through ReplaceAll. Markdown/text folder capture rejects reparse points, invalid UTF-8 and oversize data. Limits: 10,000 scanned entries, depth16, 1,000 files, 100,000 characters/note and 25 MiB serialized data. Image references remain literal. Static JsonStore.Read/Export are explicit plaintext interchange, requiring host confirmation for protected data exports.

Verification uses synthetic source suites and actual packed-artifact work/expansion-consumer (PackageReference only, isolated local cache/feed). It covers persistence, folders/tags/search/tasks/checklists, attachments, encrypted copy and portable restore. See expansion checks for actual command outcomes; installer upgrades, physical DPI/pickers and accessibility/performance certification are outside these checks. Importing the assembly performs no IO; constructing an owner explicitly creates/locks its directory.

Archive foundation: use `ArchiveMutationService(owner, existingNotebookService)` for canonical Desktop mutations. Reads/prepare throw `DataException`; mutations return `Outcome`. Inspect/reconcile the pending journal before writable library normalization. `LibraryStore.ReadRaw` preserves source metadata for deletion capture. Content history restores only title/body/flair and destination; Trash restores captured IDs/timestamps, nested replies, metadata and verified archive-owned attachment bytes. An absent notebook is recreated unless a destination is explicitly supplied; changed identities conflict. Retained archives remain after restore until explicit permanent deletion.

Every archive file uses owner.Files, including encrypted copies and portable restore validation. Prepared stages and fingerprints support retry after canonical or metadata failure; this is a recoverable sequence, not a multi-file atomic transaction. Pending/corrupt/future journal blocks gateway mutations. Explicit cancellation is allowed only when both canonical and library still match the prepared before-state. Limits: 512 MiB aggregate archive/stages, 5,000 entries, 20 history entries per note, existing payload and whole-copy limits. No automatic purge. Failed preparation may retain unreferenced staged files, which continue to count against capacity; automatic orphan cleanup is intentionally absent. UI integration and independent audit are separate gates.

Archive correction contract: pending journals bind every preservation entry (and a restore source) to its immutable descriptor SHA256/length. Reconciliation, portable creation/restore, and encrypted-copy source/target verification validate those exact descriptors and their payload closure, including absent descriptors. Permanent removal refuses pending operations. A verified committed operation records cleanup readiness before removing stages and deletes its journal last; interrupted cleanup remains retryable without dropping archive references. Cancellation can leave orphan stages if cleanup fails; retained orphan files still count toward aggregate capacity and are never automatically purged.

Folder snapshots contain only captured notebook assignments and their ancestor closure. Explicit destination restores retain the destination's current folder provenance. Preservation detects note changes with a single indexed after-state; full archive validation still reads all retained payloads on canonical mutation (up to 512 MiB), and capture can repeat that validation. This remains an unmeasured latency risk; no performance certification is claimed. Internal test-only owner budgets can only lower production caps through Math.Min; production limits remain 512 MiB/5,000 entries/20 versions. Internal provider hooks are unset in normal operation and run after temporary flush/before replacement or before explicit deletion.

Gateway History capture stores the previous Note record (including Saved and timestamps for display) and its necessary notebook, with empty replies and LibraryState and no attachment descriptors or blob copies. Restoring content preserves CURRENT replies, bookmark, tags, tasks and attachment bytes; restoring a version archives the displaced content with the same lean scope. Trash still captures the complete deleted tree, metadata and attachment bytes before deletion. Schema 1 and the generic ArchiveStore API are unchanged; existing richer History remains readable without rewriting or purging it. ValidateAll still scans retained archive payloads: save cost remains bounded by retained bytes/entries and is a beta performance limitation, not a full-capacity performance certification.

### Pre-preparation recovery binding
`ArchiveMutationService.Execute(command, canonicalRevision, libraryRevision, beforePrepare)` adds an optional identity persistence step while retaining the original three-argument API. A validated frozen candidate is supplied exactly once, before preservation, stage or journal writes, and that same candidate is committed. Return a failed `Outcome` to abort without those writes. The callback may persist recovery only: it must not mutate canonical/library data or reenter gateway operations. Reentrant mutations are refused; canonical/library identities and revisions are checked again after callback success. Identity allocation is not evidence of canonical commit. Callers must retain and reconcile the exact ID; missing bound IDs require explicit replacement authorization.
